# Soapy Panels 1.2.1-rc.1 — Linux release draft

Status: prepared locally; not published. Ubuntu CI and the manual acceptance
checklist remain release gates. See [validation results](linux-validation.md).

## Release notes

This candidate packages the Linux Community edition as an x64 AppImage for
Intel/AMD desktops. Themes and MP4 export are included, without advertising or
Microsoft Store purchases.

The candidate includes the current editor improvements: project recovery,
selection alignment guides, image-filter previews, GIF resource limits, and
private export staging. Linux release validation now exercises the packaged
application, including project recovery, file operations and media exports.

The AppImage launcher preserves Chromium sandboxing. Systems that prevent its
sandbox from starting need compatible application-specific host policy; the
launcher no longer silently falls back to an unsandboxed process.

## Assets to attach

- `Soapy.Panels-1.2.1-rc.1-x64.AppImage`
- `Soapy.Panels-1.2.1-rc.1-x64.AppImage.sha256`

Use the checksum file generated alongside the final artifact. There is no ARM64
or Debian package in this release. Download and verify both assets, make the
AppImage executable, then run it as your normal user. The application includes
its Electron runtime; Node.js and npm are not prerequisites.

See [installation and validation instructions](../../LINUX_APPIMAGE_SMOKE_TEST.md)
for FUSE dependencies, extraction fallback, manual upgrades and desktop checks.

## Known validation limits

Ubuntu 22.04/24.04 CI runs must pass before the tag workflow publishes. A local
Zorin test cannot establish compatibility with the default Ubuntu AppArmor
policy. Clean-host tests without development tooling, real native file dialogs,
external playback inspection, separate X11/Wayland sessions and upgrade testing
remain manual acceptance items.

The configured dependency audit passes with zero production advisories and six
moderate build-tool advisories (the minimatch dependency chain). No dependency
versions were changed as part of Linux release preparation. Broad pre-existing
lint cleanup remains separate from release tooling validation.
